# Alphabet Safari for iPhone and iPad

A small native app around the same web app as the website and the Android app. Nothing is
copied into `ios/`: at build time Xcode stages the web files from the repo root
(`build.py --site-dir`), so all platforms always ship the same content.

| Piece | File |
|---|---|
| Xcode project, as text (XcodeGen) | `project.yml` |
| Full-screen web view, kept inside the safe area; network blocked; only bundled pages load | `AlphabetSafari/WebViewController.swift` |
| `window.NativeBridge`: speech (AVSpeechSynthesizer, on-device voices), haptics | `AlphabetSafari/WebBridge.swift` |
| App icon (generated by `sync_assets.py`), launch colour, privacy manifest | `AlphabetSafari/Assets.xcassets`, `PrivacyInfo.xcprivacy` |
| UI tests on iPhone and iPad simulators, with an in-page self-test | `AlphabetSafariUITests/` |

## Built and tested by CI

`.github/workflows/ios.yml` runs on GitHub's macOS runners whenever something the app is built
from changes. It generates the project, builds it, and runs the UI tests on the largest iPhone
and iPad simulators. The self-test (`AlphabetSafariUITests/selftest.js`, the counterpart of
`tests/android-device.mjs`) checks the native bridge, recorded clips, fonts (including the drawn
pomegranate), speech, that the internet is blocked, the privacy policy, the layout in portrait
and landscape, and that the chosen language survives a relaunch. Its report and any errors appear
as annotations on the run; screenshots are in the `AlphabetSafari-iOS-Test-Results` artifact.

## Building on a Mac

```bash
brew install xcodegen
cd ios && xcodegen generate && open AlphabetSafari.xcodeproj
```

## Decisions

- **Silent switch:** sound plays even when the ring/silent switch is on (`AVAudioSession`
  category `.playback` in `AppDelegate.swift`), since the letter sounds are the lesson. Change
  it to `.ambient` to follow the switch.
- **No network:** a content rule blocks every `http(s)`/`ws(s)` request inside the web view, so
  the privacy policy's "no internet" promise holds on iOS too (iOS has no internet permission
  to leave out, as Android does).
- **Safe area:** the web view sits inside the safe area natively; the page's own
  `env(safe-area-inset-*)` padding is for the home-screen web app in Safari.
